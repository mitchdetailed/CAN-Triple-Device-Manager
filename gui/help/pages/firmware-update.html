Updating Firmware

Online → Update Firmware… installs new firmware on a connected device over the serial link. No debugger, no dismantling the installation.

What happens, and why it is safe

The image is not written over the running firmware. It is sent to a spare area of the device's flash — the staging area — while the device carries on running normally, still handling CAN traffic throughout. Only when the whole image has arrived and the device has checked it does it restart and install.

That ordering is what makes an interrupted update harmless. If the cable is pulled, the program is closed, or the image turns out to be corrupt, the device is still running exactly the firmware it started with. The worst outcome is a wasted few seconds.

Even a power cut during the install itself is survivable: the staging copy is kept intact until the new firmware is verified in place, so the device simply finishes the job the next time it powers up. It will retry the install up to three times; a unit interrupted that many times in a row needs an ST-Link.

On a CAN Triple 2.0

A CAN Triple 2.0 keeps copies of its firmware: the version it runs, the one before it, and the one it left the factory with. An update is stored beside the running version, never over it, and after the restart the new version runs on trial. Update Firmware ends the trial as soon as the unit answers again, and the unit ends it by itself after a minute of running.

If the new version does not start properly, so that the unit keeps restarting before the trial ends, the unit goes back to the version it had before, by itself, after three starts. The Device panel then says so, naming the version that did not start. If the installed firmware is ever found damaged when the unit starts, the unit writes it again from its copy and says that too.

The Device panel lists the copies: Firmware kept on the unit: A 2.0.1 (running), B 2.0.0 (previous), factory 2.0.0. The previous copy is the one a failed update goes back to; the factory copy is the last resort.

Doing it

  1. Connect to the device as usual (Tools → Connection Settings…).
  2. Open Online → Update Firmware…. The Device panel shows what is currently running.
  3. Browse… and pick the .ctf file you were supplied. The program checks it immediately, using the same test the device itself applies — a damaged or wrong-product file is refused here, before anything is sent. The firmware that came with this Device Manager is in its install folder, under Firmware: the CAN Triple's there (its variants in Variants), and the CAN Triple 2.0's in CAN Triple 2.0, where Browse… opens when a CAN Triple 2.0 is connected.
  4. Read the warnings, if any (see below).
  5. Leave Save a copy of the device's configuration ticked.
  6. Update Firmware.

A 55 KB image takes roughly six seconds to send, and the device is back about two and a half seconds after it restarts. The progress bar sits still for a moment at the start while the staging area is prepared — that is erasing, not a hang.

The configuration backup

Some firmware updates change the format the configuration is stored in. When that happens the device's saved configuration cannot be read by the new firmware and the unit starts up with nothing configured. The configuration cannot be recovered from the device afterwards — reading it out beforehand is the only opportunity.

So the update reads the configuration out first and saves it as a dated .ct3 file in:

Documents\CAN Triple Device Manager\Firmware Update Backups\

If the device does come back empty, the program offers to send the backup straight back. On a password-protected device you will be asked for the Send Configuration password again at that point — the restart clears the device's memory of it, which is expected.

If the backup fails, the update does not start. Continuing would destroy the very thing the backup was protecting.

Warnings you may see

WarningWhat it means
This update changes the stored-configuration format The device will start up with no configuration. Keep the backup ticked; the program will offer to restore it afterwards.
This image lays the configuration out differently from the firmware the device is running The image is a different variant of the firmware — the same version with some tables sized differently (the message lists which: "CRC8 rules: 20 → 40"). The device stores a configuration only for the layout that wrote it, so it will start up with no configuration exactly as for a format change. Keep the backup ticked. After the update, open the document and set File → Target Firmware… to the connected device before sending, so the document is sized for what the unit now holds.
This image is OLDER than the firmware the device is running Going backwards is allowed, but rarely intended. Check you picked the right file.
The device is already running version … Harmless, but it will not change anything.
This device has no bootloader The unit is running firmware from before over-the-wire updates existed. It needs a one-time update using an ST-Link debugger; after that it can be updated from here like any other. Update Firmware stays disabled until then.
This image needs bootloader version … The file is newer than this unit's bootloader can install. You need either an older image or a bootloader update over ST-Link.
This image is firmware for the CAN Triple 2.0, and this unit is a CAN Triple (or the reverse) There are two boards, the CAN Triple and the CAN Triple 2.0, and each takes its own firmware. The Device panel names the board, and the file's panel names the board the file is for. Pick the file for this unit's board.
This unit is a … This version of the Device Manager does not update that board The unit is a board newer than this program. Update the Device Manager.
… is firmware for the CAN Triple 2.0 Shown when you pick the file, not as a warning: the file is for the other board. A unit installs only firmware built for its own board, and every version of this program and of the device's own firmware refuses the other's.

If something goes wrong

Reopen Online → Update Firmware… — the Device panel reports what happened on the last attempt, including anything that failed while nothing was connected to hear about it.

MessageWhat to do
The device refused the image The file did not arrive intact. Try again; if it keeps happening, the file itself is probably damaged — get a fresh copy.
Last install attempt failed: checksum does not match Same cause, caught after the restart. The previous firmware is still running and unharmed.
The device did not come back within 25 seconds (60 for a CAN Triple 2.0) Wait a little longer, then reconnect and reopen this dialog. The install either finished or was never started; either way the device is running valid firmware. A CAN Triple 2.0 whose new firmware does not start goes back to the firmware before it by itself; turning it off and on counts as one of the three starts that takes.
Firmware … did not start properly, so the unit went back to the firmware it was running before CAN Triple 2.0 only. The previous firmware is running and unharmed. Do not install that file again; tell whoever supplied it.
The installed firmware was found damaged at start-up and was written again from the unit's stored copy CAN Triple 2.0 only. Nothing to do: the unit repaired itself. If it keeps happening, the unit may have a hardware fault.
… is early CAN Triple 2.0 firmware, from before the 2.0 firmware line Shown when you pick the file. It was made for the first CAN Triple 2.0 boards before their firmware line began, and does not run on a unit that has the line. Use a 2.0.0 or later file.
The device is password protected The update asks for the Send Configuration password and, on a unit that also guards "Get a Configuration", for that password as well: the dialog cannot read the device's firmware status or take a configuration backup without it. Cancelling either prompt leaves the update closed. The restart at the end of an update clears the device's memory of both; the dialog proves the Get password again by itself. If this message appears anyway, close the dialog and open it again to be asked afresh.
The device could not write its flash (0x05) If it happens on every attempt, the unit's flash is set to single-bank mode, where the firmware refuses updates and licences. Run the CAN Triple Initial Programming Tool from the Start Menu with the unit connected: it reads the flash mode, switches it to dual-bank, and programs the firmware. The switch erases the whole chip, stored configuration included, so use Get Configuration and save it first, then Send it back afterwards.

A device whose front LED is flashing rapidly and which does not answer at all has no valid firmware to run and needs an ST-Link. This should not happen from a failed update — the running firmware is never touched until a replacement has been fully verified — but it is what a physically damaged unit looks like.

Each board takes only its own firmware. The dialog shows which board a file is for, and a CAN Triple 2.0 file is refused for a CAN Triple, and the reverse, naming both. See The CAN Triple 2.0.

The Initial Programming Tool reads which board is attached before it erases or writes anything. It programs the CAN Triple; on a CAN Triple 2.0, or on anything that is not a CAN Triple, it says what it found and stops with Action Not Completed.
