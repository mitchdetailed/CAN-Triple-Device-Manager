4. mingw-w64 runtime, statically linked into CANTripleDeviceManager.exe
================================================================================

File redistributed
    None of its own. This code is linked into CANTripleDeviceManager.exe itself
    and has no separate file anywhere in the distribution.

What it is
    The mingw-w64 project's C runtime for Windows: the CRT startup objects
    that run before main(), and libmingwex, which supplies the standard C
    functions that the Microsoft C runtime shipped with Windows does not
    provide - among them the floating-point conversion code (gdtoa) behind the
    printf family, and parts of the maths library. GCC links these objects
    into every executable it builds for this target, so they end up inside the
    .exe rather than in a DLL beside it.

Version
    mingw-w64 runtime v11.0, x86_64-w64-mingw32, from the same MinGW-Builds
    GCC 13.1.0 toolchain that supplied the libraries in sections 2 and 3.
    Unmodified.

Licence
    Permissive, and not a single licence but a set of notices: the mingw-w64
    project's own terms for the runtime as a whole, plus separate notices for
    the getopt implementation, for the gdtoa floating-point conversion code,
    and for the parts of the maths library that came from Sun Microsystems and
    from the Cephes library. The mingw-w64 project collects all of them into
    one file, COPYING.MinGW-w64-runtime.txt, which opens by stating that parts
    of the runtime are under licences requiring the copyright and licence
    notices to be included when the code is distributed in binary form. That
    file, as distributed with the toolchain, is reproduced verbatim between
    the markers below.

9. OpenOCD (with libusb and libftdi), in the initial-programming kit
================================================================================

Files redistributed
    Firmware\openocd\bin\openocd.exe
    Firmware\openocd\bin\libusb-1.0.dll
    Firmware\openocd\bin\libftdi1.dll
    Firmware\openocd\scripts\interface\stlink.cfg
    Firmware\openocd\scripts\target\swj-dp.tcl
    Firmware\openocd\scripts\mem_helper.tcl

What it is
    The Open On-Chip Debugger. CANTripleInitialProgramming.exe (part of
    CAN Triple Device Manager, MIT, source in the repository at the top of
    this file) invokes it as a SEPARATE PROGRAM - a child process, not a
    linked library -
    to program the device's bootloader and application over the board's
    built-in ST-LINK. The two .dll files are libraries OpenOCD itself loads
    for USB access; the .cfg/.tcl files are configuration scripts from
    OpenOCD's own distribution. (stm32g4x_512k.cfg in the same directory is
    NOT OpenOCD's: it is this project's, a one-line variant of OpenOCD's
    stm32g4x.cfg, and is covered by COPYING.txt like the rest of the
    project's own files - its provenance is documented in its header.)
